## 1. P0 级（会让策略自锁 / 统计失真 / 必然亏钱）

### P0-1 `psCycleMs` 漏扣 `psFlowMs` → 开 2 个仓后永久停买
- **位置**：`main()` 循环末尾
- **问题**：注释写明"链上成交解析耗时不计入数据延迟"，但没有一处代码兑现；`psFlowMs` 是**只写不读**的死变量，`psCycleMs` 把 `Sleep(150)`×N 全算进"行情新鲜度"。按实测 RPC 量：一次 `psFetchTrades(40)` ≈ 2.2–4.2s，`pMaxPos=5` 时单轮 10–17s，直接撞 `pMaxLatency=15` → `psBlock()` 非空 → **全市场停买**，日志却只说"数据延迟 Xs"，人会误判行情。
- **修复**：`psCycleMs = Date.now() - t0 - psFlowMs;`

### P0-2 成本模型漏 ATA 租金 + 单笔尺寸落在摩擦最重区间
- **位置**：`psTxFee()`、`psEvaluate()` 的 `roundTrip`、`psBuy()` 模拟成本
- **问题**：`psTxFee()` 只有"优先费 + 0.000005"。0.05 SOL 的单子，真实往返 = 曲线费 2.5% + 冲击 0.5% + 优先费 2.0% + **ATA 4.08%** = **8.39%**，而策略内部模型算 2.02%，门槛 `pMaxRoundTrip=8` 恰好设在盲区 → **筛不掉任何东西**。
- **修复**：
  - 新增 `pAtaReclaim`（1=卖出后关闭代币账户回收，0=计入成本）/`pAtaCost`（0.00204）；
  - 新增 `psAtaFee()`/`psTryCloseAta()`，全平后调用；
  - `roundTrip` 与模拟成本均计入 `psAtaFee()`；
  - `pBuySol 0.05→0.20`、`pMinBuySol 0.01→0.05`（0.01 SOL 的固定成本是 -27.6%/笔）。

### P0-3 影子评估把毕业样本记 `null` 并剔除 → 幸存者偏差方向反了
- **位置**：`psShadowValue()`、`psShadowTick()`、`psShadowAgg()`
- **问题**：毕业 = 表现最好的那批（20% 进度到毕业 5.55 倍），被 `x.grad=true; return null` 后在 `psShadowAgg` 里被 `typeof === "number"` 过滤，**从均值和胜率中整体删除**。用这种数据调参必然把阈值越调越松。
- **修复**：新增 `psGradReturn(prog)`，按策略自身出场规则（`pExitProgress` 前退出）用曲线定价反算：`((30+85·ep)/(30+85·p))² - 1`，再扣 1.25% 与 `x.fee`。20% 进度 → **+455%（5.55x）**，进均值。

### P0-4 评分满分线按"活着"校准，不是按"金狗"校准
- **位置**：`psCfgLoad()` 默认值 + `psScore()` 的 `spread`
- **问题**：`goodSlope=3pp/分`（真实毕业中位 **19pp/分**）、`goodNetSol=3`（中位 ~19）、`goodBuyers=10`（中位 457 笔）→ 任何"还活着"的币六项全满，`minScore=60` 会放进 **69.7 分的慢磨死币**。
- **修复**：`goodSlope 3→10`、`goodNetSol 3→20`、`goodBuyers 10→40`、`minScore 60→80`、`minBuyers 5→25`；
- **`spread` 分母改为流通量**（曲线期只流通 24%~78%，用 1e9 会让 15 分几乎恒满）→ 阈值改 `top10` 35% 满分 / 70% 归零。

| 原型 | v3.2 得分 | v3.3 第一版（按毕业量级） | v3.3 最终版（按入场量级） |
|---|---|---|---|
| 死币 | 8.2 | 2.9 | 7.0 |
| 慢磨活币 | 69.7 | 42.0 | 75.3 |
| 对倒刷量包 | 85.0 | 80.9 | 97.9 |
| 真实毕业生中位 | 91.0 | 99.0 | 100 |

**这里我纠正过自己一次，必须写下来**：第一版我把三个满分线按「毕业中位（19pp/分、19 SOL/分、40 买家）」校准，
结果在真实数据上候选池最高只能打到 **55 分**，`minScore=80` 等于**永不开仓**。
评分函数只需要在**它实际看到的那个阶段**做排序，所以最终版把满分线改回**入场阶段 p90**（5pp/分、3 SOL、10 买家）。
评分是**排序器，不是概率**；阈值应该按「候选池的分位数」来定，而不是按「能不能毕业」来定。

## 6. 真实数据推翻了我自己的两处判断（诚实记录）

采集 175 个真实新币 / 10,466 笔真实成交（8 分钟样本，`collector2.mjs`）后得到三个硬结论：

1. **`pMinBuyers=25` 会让策略永不开仓**。597 个币里，能在"进度10~60%"区间内让 90 秒窗出现 ≥20 个独立买家的：**0 个**；≥8 的有 3 个（0.5%）；≥15 的 1 个。
   我第一版把它从 5 提到 25 是错的方向 —— 这个数字应该在**入场阶段**的分布里取分位数，而不是套用毕业统计。
2. **`年龄≥100s + 进度10~60%` 这条闸门 = 专买阴跌**。实测 12 个曾到 10% 进度的币，**10% 进度全部出现在 t=0**（dev + 捆绑盘一口买上去），
   峰值只有 14%~47%，此后一路阴跌。等 100~180 秒再进，等于在别人出货时接盘。这不只是参数问题，是入场结构问题。
   → 已把 `pMinAgeSec` 降到 45，并新增 `pMinSlope=1.5` 硬闸门（斜率不够不买）。
3. **评分函数必须按"它实际看到的阶段"校准**。第一版按毕业量级校准后，真实候选池最高只能打到 55 分，等于把策略关死。

> 这三条都是"跑真数据"才暴露的，纸面回测与拍脑袋调参都发现不了。
> 下一步的正确做法不是继续调参，而是**连续采集 5~25 天**（达到 N≈254 笔），
> 用 `calib.py` 重算分位数、用 `funnel.py` 看漏斗、用 `backtest.py` 看评分单调性，再定参数。
