# pumpfun-graduation-lab

> 用**真实链上数据**验证 pump.fun 打新策略到底能不能赚钱 —— 以及哪种入场规则才能赚钱。

这不是一个"梭哈机器人"。这是一个**可复现的验证框架**：自建 tick 采集 → 真实前瞻回测 → 链上核验结局 → 纸面 A/B 对照 → 极小金额实盘校验。

<p align="center">
  <b>核心结论：pump.fun 打新的胜负手不在出场，在入场。</b><br/>
  同一个市场、同样的出场规则，只换入场条件，期望从 <b>-19%/笔</b> 变成 <b>+51%/笔</b>。
</p>

---

## 一、这个项目解决了什么问题

网上 99% 的 pump.fun 打新机器人都在做同一件事：**看到新币就买，涨了卖，跌了止损**。
问题是没人告诉你：**这套逻辑的期望是负的，亏在哪一步。**

这个项目用 6 万+ 个真实新币、460 万+ 笔真实成交，把这个问题拆成了可量化的几块：

| 问题 | 答案（实测） |
|---|---|
| 新币有多大概率毕业？ | 全部新币中约 **0.2%**；曾到过 50% 进度的币中 **46.5%** |
| 毕业收益是多少？ | 从 50% 进度买入持有到毕业 **+108%**；从 60% 进度 **+82%** |
| 不毕业的亏多少？ | 30 分钟超时清仓平均 **-53%**，中位 **-77%** |
| 打平的毕业率要求？ | **≥33%**（低于这个数，长期必亏） |
| 那为什么还是亏？ | 因为"买入的时机"决定了你拿到的是 21% 还是 76% 的毕业率 |

## 二、核心发现：入场规则决定一切（400 个带链上标签的样本）

同样是"进度跨过 50%"这个信号，**怎么买**的结果天差地别：

| 入场规则 | 样本 | 毕业率 | 期望/笔 |
|---|---|---|---|
| 跨过 50% **立刻**买 | 400 | 46.5% | +21.9% |
| 跨过后 **60 秒仍守住 ≥50%** 才买 | 143 | **76.2%** | **+69.7%** |
| 跨过后 60 秒内**跌到 <30%**（假突破） | 90 | **4.4%** | **-45.8%** |
| 首笔成交到跨线 **<10 秒**（秒拉） | 181 | 69.1% | +58.2% |
| 首笔成交到跨线 10~30 秒（磨上去） | 44 | 25.0% | -12.8% |
| 首笔成交到跨线 30~60 秒 | 43 | 20.9% | -19.3% |

**规律：**

- ✅ **真金狗要么"一秒拉穿"，要么"拉完守住"** —— 庄家控盘强、有人接力
- ❌ **死掉的是"磨了半分钟才上去、然后掉头"的** —— 这是最典型的接盘形态
- 🚫 **跨过后 60 秒内跌到 30% 以下 = 毕业率仅 4.4%** —— 这是最强的负面信号

## 三、这套框架怎么工作

```
                 ┌──────────────────────────────┐
                 │  collector2.mjs              │  公共 WS 订阅 pump 程序日志
                 │  解析 Anchor TradeEvent      │  → 真实买卖方向/金额/交易人
                 └───────────┬──────────────────┘
                             │ data/trades.jsonl（每日 400MB）
                             ▼
      ┌──────────────────────┴───────────────────────┐
      │  research/  离线验证                          │
      │  · grad.py      条件毕业率 vs 打平线          │
      │  · hold.py      持有到毕业的期望              │
      │  · backtest.py  真实 tick 回放入场/出场规则   │
      │  · label400.mjs 链上核验 complete 标志        │
      └──────────────────────┬───────────────────────┘
                             │ 找出有正期望的入场规则
                             ▼
      ┌──────────────────────────────────────────────┐
      │  trader/graduation.mjs   纸面/实盘引擎        │
      │  · 两种入场规则可切换（confirm / fast）        │
      │  · 不设止损止盈，毕业即卖 / 超时清仓           │
      │  · 账本持久化，重启不丢仓位                    │
      └──────────────────┬───────────────────────────┘
                         │ 纸面验证通过后
                         ▼
      ┌──────────────────────────────────────────────┐
      │  trader/buy_live.mjs / sell.mjs / sell_now.mjs│  真钱执行
      │  · 官方 pump-sdk 构造指令（不是猜接口）        │
      │  · 毕业后的币用 Jupiter 聚合器卖（路由到 AMM） │
      └──────────────────────────────────────────────┘
```

### 关键工程细节（都是踩坑换来的）

| 坑 | 症状 | 解法 |
|---|---|---|
| **Token-2022** | `IncorrectProgramId`，交易永远失败 | 新币 100% 是 Token-2022，必须显式传 `tokenProgram` |
| **迁移瞬间储备归零** | 把已毕业的币判成"亏光 -100%" | 不能用"储备归零"判毕业，要查链上 `complete` 标志 |
| **半开 WS 连接** | 行情静默卡死，`ws.close()` 不触发 `onclose` | 看门狗 12 秒无消息 → 强制丢弃旧 socket 重建 |
| **异步买入无锁** | 同一个币被买两次，仓位翻倍 | 每币 `pending` 锁 |
| **pending 自锁** | 永远不买入（自己把自己锁住） | 锁只能由调用方持有，被调函数不能再判断 |
| **余额耗尽** | 卖不出去（`InsufficientFundsForRent`） | 必须留手续费储备；应急清仓用优先费=0 |
| **模拟盘重启归零** | 常驻运行白跑 | 账本持久化到 JSON，启动时恢复持仓 |

## 四、快速开始

### 1. 装依赖

```bash
cd trader
npm install @solana/web3.js@1 @pump-fun/pump-sdk bn.js @solana/spl-token
```

### 2. 配 RPC

复制 `config.example.json` 为 `trader/config.json`，填入你的 RPC。或者用内置向导（Key 不会回显）：

```bash
python trader/set_rpc.py
```

> **免费档够用**，但要注意分工：
> - **HTTP 查询** → 走付费/免费档 RPC（Helius 1 credit/次）
> - **WS 全量行情** → 走公共节点（`wss://solana-rpc.publicnode.com`）
>
> 原因：Helius 的 WS 按流量计费（2 credits/0.1MB），收全量 pump 日志实测 **377 KB/s ≈ 63.7 万 credits/天**，免费档 1.6 天烧光。

### 3. 采集数据（可选，用于研究）

```bash
python supervisor.py            # 常驻，每天 00:00:10 日切归档
```

### 4. 跑纸面引擎

```bash
python grad_supervisor.py            # 常驻，并行跑 confirm / fast 两组
python grad_supervisor.py --status   # 看两组账本
python grad_report.py                # 生成日报
```

### 5. 上真钱（先用 0.01 SOL 验证）

```bash
# 导入私钥（隐藏输入，不落日志）
python keys/import_key.py

# 只读校验：算报价、模拟交易，不签名不发
node trader/dryrun.mjs <mint>

# 真实买入 / 卖出
node trader/buy_live.mjs <mint> --confirm
node trader/sell.mjs <mint> --confirm

# 应急清仓（余额只剩几千 lamports 也能卖）
node trader/sell_now.mjs --confirm
```

## 六、这个项目**不**承诺什么

- ❌ 不承诺盈利。纸面正期望不等于实盘盈利（滑点、失败交易费、RPC 限流都会吃掉利润）
- ❌ 不支持历史回测。策略依赖实时链上状态，只有前视纸面 + 极小金额实盘才算数
- ❌ 不是"全自动印钞机"。它需要你理解入场规则为什么有效，否则参数一改就失效

**已知的实盘成本（0.02 SOL 单笔）：**

| 项目 | 金额 | 占比 |
|---|---|---|
| 买卖手续费（1.25%×2） | 0.0005 SOL | 2.5% |
| 优先费（两笔） | 0.0010 SOL | 5.0% |
| 代币账户租金（可回收） | 0.0015 SOL | 7.6% |
| 失败交易费（滑点/限流） | 视行情 | 5~20% |

> 单笔低于 0.01 SOL 时，固定成本占比会超过 25%，**没有统计意义**。
